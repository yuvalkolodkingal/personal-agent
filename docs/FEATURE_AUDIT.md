# Personal Agent implementation audit

This file records what the desktop app actually supports as of 2026-08-27. “Partial” means useful core code or a read-only surface exists, but the full user workflow is not connected end to end.

| Area                       | Status      | Current implementation                                                                                                                                          | Remaining work                                                                       |
| -------------------------- | ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| Chat, providers and models | Implemented | Authenticated pinned OpenCode sidecar, OAuth/API-key connections, model discovery, one global model picker, streamed turns, stop and timeout recovery           | Continue compatibility testing as OpenCode APIs evolve                               |
| English STT/TTS            | Implemented | Moonshine Medium Streaming, Smart Turn v3.2 and Qwen3-TTS 0.6B; Whisper and Piper fallbacks; Voice Lab status/install controls                                  | Hardware-specific performance tuning and broader packaging tests                     |
| Persistent memory          | Implemented | Encrypted per-profile snapshot, explicit saves, conversational follow-up capture, lexical recall, prompt injection, provenance, approval/rejection and deletion | Generate pinned embeddings for semantic/vector recall and add conflict-resolution UI |
| Sessions/history           | Implemented | Create/resume/rename/delete, bulk selection, bounded recent list, search/filter and recovery from stale sessions                                                | Optional archive/export workflows                                                    |
| Goals/tasks                | Partial     | Durable domain types, state transitions, event persistence and creation UI                                                                                      | Connect the task-graph supervisor and controls to live OpenCode agent execution      |
| Browser                    | Partial     | Domain allow/deny policy, download limits and safety boundary                                                                                                   | Wire an interactive embedded browser/controller and visible permission flow          |
| Projects/terminal          | Partial     | OpenCode file, search, VCS, worktree and PTY resource views                                                                                                     | Persistent interactive terminal and richer editor/diff workflows                     |
| Artifacts                  | Partial     | Durable artifact creation metadata and events                                                                                                                   | Editors, previews, version history and restoration                                   |
| Automations                | Partial     | Tested scheduler engine, recovery model and encrypted snapshots                                                                                                 | Connect desktop forms to scheduler persistence and run a resident executor           |
| Integrations/skills        | Partial     | OpenCode provider auth plus MCP, command and agent catalog visibility                                                                                           | Connector marketplace, install/connect lifecycle and per-connector controls          |
| Usage/egress               | Partial     | Auditable local runtime/tool events and secret-free diagnostic export                                                                                           | Normalize provider token/cost metrics and retain structured egress entries           |
| Notifications              | Not wired   | Configuration schema and routes                                                                                                                                 | Native desktop delivery, actions and quiet-hours enforcement                         |
| Updates                    | Not wired   | Release verification/config primitives                                                                                                                          | Signed update feed, download UI and atomic installer                                 |

The app deliberately does not grant unrestricted filesystem, shell, browser or connector access directly from model text. Those effects must pass through authenticated OpenCode capabilities and the native policy boundary.

# Legacy audit

The legacy input is `/home/yuval/Documents/GitHub/Jarvis` at commit
`89a87df90614adf3422f0f1fb2ba41ac4dafb522`. It was inspected read-only and
remained clean on `main` during bootstrap.

The audit is generated by `scripts/generate-legacy-inventory.py` and committed
as `legacy-capabilities.yaml`. It currently contains 1,149 mappings across:

- 109 Python modules;
- 50 CLI commands;
- 177 configuration fields in 28 dataclass sections;
- 125 focused test modules;
- 479 documented feature headings;
- 196 explicit platform/limitation statements;
- 13 migration input classes.

The generator reads Git-tracked source paths, parses the command tuple, imports
only the legacy configuration dataclasses to enumerate fields, extracts
documentation headings/limitation statements, and adds the specification’s
migration inputs. It writes only to the new repository. CI validates that each
mapping points to an existing capability and acceptance test.

Inventory mapping is not equivalent to feature completion. `legacy_status` and
acceptance status in the other registries decide whether behavior is passed,
equivalently replaced, pending, or rejected for a documented reason.
